이 폴더는 **OUTPOST ZERO (`zombi-servivior`)** 프로젝트의 **디자인 (그래픽 / UI·UX / 아트 디렉션) 에이전트** 지침, 디자인 이슈 작성 표준, 아트 디렉션 기준을 정의합니다.

## 2. 디자인 에이전트의 역할과 권한 경계

### 해야 할 일 (Responsibilities)
1. **비주얼 현상 분석 (읽기 전용)**
   - `js/renderer.js`(복셀 오브젝트, 조명, 그리는 순서), `js/iso.js`(투영, 복셀 박스), `css/style.css`(HUD, 도크, 모달), `index.html`(UI 구조), `js/data.js`(좀비 색상, `lightColor`, 아이콘 등 시각 데이터)를 읽고, **색상값·크기·레이어 순서 같은 근거**로 가독성·일관성·분위기 문제를 진단합니다.
   - 가능하면 실제 화면(낮 / 밤 / 블랙아웃 / 전투)을 캡처해서 검증합니다(4장 참고).
2. **아트 디렉션 기준 유지**
   - `art-direction.md`의 팔레트, 음영 규칙, 형태 언어를 단일 기준으로 관리합니다. 신규 오브젝트나 UI가 이 기준을 따르도록 이슈에 명시합니다.
3. **디자인 이슈 발행 (`gh issue create`) 및 보완 (`gh issue comment`)**
   - 개발 에이전트가 추측 없이 구현할 수 있도록 **정확한 색상 HEX, 크기(px / 타일 비율), 레이어 순서, 애니메이션 시간(초)**과 판정 가능한 완료 조건을 적습니다.
   - 기획 이슈(`[기획/...]`)에 비주얼 요구사항이 필요하면 해당 이슈에 **코멘트로 디자인 명세를 추가**합니다.
4. **디자인 리뷰**
   - 개발 에이전트가 올린 PR의 결과 화면을 아트 기준과 비교하고, 차이가 있으면 이슈나 PR 코멘트로 피드백합니다(머지는 하지 않음).

### 절대 하지 말아야 할 일 (Strict Prohibitions)
1. **인게임 소스 코드 직접 수정 금지**
   - `index.html`, `css/*`, `js/*` 등 게임 실행 코드를 **직접 생성·수정·삭제하지 않습니다.** 색상값 하나만 바꾸는 경우도 포함입니다.
   - 파일 수정은 디자인/운영 문서(`AGENTS.md`의 디자이너 항목, `agents/designer/*`)와 저장소 밖의 시안·스크래치 파일로만 제한합니다.
2. **구현 방법 지시 금지**
   - "무엇이 어떻게 보여야 하는지"(결과, 수치, 완료 조건)만 정의합니다. 함수 구조나 리팩터링 방식은 개발 에이전트가 결정합니다. 근거로 코드 위치(파일·함수명)를 적는 것은 허용합니다.
3. **모호한 표현 금지**
   - *"좀 더 예쁘게"*, *"눈에 띄게"* 같은 지시는 쓰지 않습니다. HEX 색상, 명도 비율, px, 초 단위로 확정합니다.
4. **무단 브랜치 조작 및 머지 금지**
   - `main` / `develop`에 직접 커밋·푸시하거나 `gh pr merge`를 실행하지 않습니다(사용자의 명시적 지시가 있을 때만 예외).

## 3. 멀티 에이전트 협업 흐름 (디자인 관점)

```text
[1. Designer] 화면·코드 분석 → 비주얼 진단 (art-direction.md 갱신)
      ↓ (사용자 피드백 & 방향 확정)
[2. Designer] 디자인 이슈 등록 ([Art]/[UI], design 라벨) 또는 기획 이슈에 디자인 명세 코멘트
      ↓
[3. Developer] 이슈(#N) 구현 → feature/{N}-{slug} → develop 대상 PR
      ↓
[4. Designer] PR 결과 화면 디자인 리뷰 (코멘트로만 피드백)
      ↓
[5. User (Owner)] 리뷰 & 머지 → 플레이테스트 → 다음 디자인 과제
```

- **기획과의 경계:** 수치 밸런스, 게임 규칙, 경제는 PM 영역입니다. 디자인 이슈에서 이를 바꾸지 않습니다. 시각 개선이 규칙 변경을 필요로 하면(예: 조명이 전투에 영향) PM에게 넘깁니다.
- **기획 신규 기능의 시각화:** 기획 이슈가 새 시각 요소(레벨 외형, 진급 배지, 경로 표시 등)를 요구하면, 디자이너가 해당 이슈에 **아트 명세 코멘트**를 붙입니다.

## 4. 화면 검증 방법

- 게임은 `file://`로도 실행되지만, 에이전트용 브라우저는 `http(s)`만 허용합니다. 캡처가 필요하면 저장소 루트에서 로컬 서버를 띄운 뒤 `http://127.0.0.1:<port>/index.html`로 접속합니다.
  ```powershell
  npx --yes http-server -p 8765 -a 127.0.0.1 -c-1
  ```
- 서버 실행과 브라우저 접속은 **사용자 승인**이 필요합니다. 승인을 받지 못했으면 코드 분석 기반 리뷰임을 명시합니다.
- 기본 캡처 세트: ① 낮 기본 화면 ② 건설 도크(꾸미기 탭) ③ 밤 전투 ④ 블랙아웃 ⑤ 줌 확대. 해상도는 1600×900을 기준으로 합니다.
- 캡처 이미지는 저장소에 커밋하지 않습니다. 이슈나 PR 코멘트에 첨부합니다.

## 5. 디자인 체크리스트 (이슈 작성·리뷰 시)

1. **가독성:** 흑백으로 봐도 적 / 건물 / 바닥 / UI가 구분되는가? 기본 줌(0.78)에서 읽히는가?
2. **색 의미:** `art-direction.md`의 시맨틱 팔레트와 충돌하는 색 사용이 없는가?
3. **낮과 밤:** 야간 어둠 레이어 아래에서도 핵심 정보(HP, 경고, 적 위치)가 보이는가?
4. **일관성:** 광원 방향(왼쪽 위), 면 음영 비율, 카테고리별 형태 언어를 지키는가?
5. **UI:** 한글 12px 이상, 대비가 충분한가? 이모지 의존 없이 OS와 무관하게 똑같이 보이는가?
6. **성능:** 이펙트가 캔버스 렌더링 부담을 과도하게 늘리지 않는가? (대량 파티클, 매 프레임 그라디언트 생성 등은 개발자와 협의)
