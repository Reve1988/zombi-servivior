# 디자인 이슈 명세 표준 및 `gh` 운영 가이드 (`design-issue-guide.md`)

디자인 에이전트가 개발 에이전트에게 작업을 맡길 때는 이 문서의 **분할 기준, 제목·라벨 규칙, 본문 필수 항목**을 지켜서 GitHub 이슈를 만듭니다.

---

## 1. 이슈 분할 원칙

1. **1 이슈 = 1 시각 문제 = 1 PR**
   - 하나의 `feature/{issueNumber}-{slug}` 브랜치로 구현하고 전후 비교가 가능한 크기로 나눕니다.
   - 예: "적 색상 재지정"과 "적 실루엣 리디자인"은 별도 이슈로 만듭니다.
2. **기반 → 적용 순서**
   - 팔레트나 음영 규칙 같은 **기반 이슈**를 먼저 만들고, 이를 사용하는 이슈 본문 위쪽에 의존성을 적습니다.
   - `> **선행 의존성**: #3 (시맨틱 팔레트) 구현 후 진행 권장`
3. **기획 이슈와 중복 금지**
   - 기획 이슈가 이미 다루는 기능의 시각 요소는 새 이슈 대신 **기존 기획 이슈에 코멘트**(`gh issue comment`)로 명세를 추가합니다.

---

## 2. 제목 및 라벨 규칙

### 제목 형식
```text
[Art] {시각 문제 또는 목표 요약}     ← 월드(캔버스) 그래픽, 조명, 이펙트, 캐릭터, 지형
[UI] {UI/UX 문제 또는 목표 요약}      ← HUD, 도크, 모달, 아이콘, 폰트, 텍스트
```
- 예: `[Art] 적(좀비)이 배경 잔디에 묻혀 보이지 않음`, `[UI] 이모지 아이콘 교체 및 폰트·텍스트 크기 정비`

### 라벨 (`--label`)
- 모든 디자인 이슈: `design`
- 의도와 다르게 보이는 렌더링 오류(예: 레이어 순서 때문에 정보가 가려짐): `design,bug`
- **파이프라인 게이트 라벨 연동 (`agents/github-communication-guide.md`)**: 임의 라벨은 신설하지 않되, 진행 상태 표시용 공식 5종(`gate:2-design`, `gate:3-dev-ready`, `gate:4-qa`, `status:merged-dev`, `status:hold`)과 해당 **Milestone**, **[Project #1](https://github.com/users/Reve1988/projects/1)** 컬럼 이동은 반드시 함께 동기화합니다. 우선순위는 본문 첫 줄에 적습니다.

### 우선순위 기준
| 우선순위 | 기준 |
|---|---|
| **P0** | 플레이 판단에 필요한 정보가 보이지 않음 (가독성, 정보 손실) |
| **P1** | 일관성, 완성도, 타격감 등 경험의 질 |
| **P2** | UI 다듬기, 장기적인 아트 업그레이드 |

## 3. 이슈 본문 및 코멘트 필수 템플릿 (단일 계정 역할 말머리 포함)

```markdown
### 🎨 [디자이너 / Designer] → @개발자 (또는 @오너 @개발자)

> **우선순위:** P0 · **분류:** design, art, readability
> **선행 의존성:** #N (없으면 생략)

### 문제
- 플레이어 입장에서 무엇이 보이지 않거나 어색한지 한두 문장으로 설명

### 근거
| 요소 | 현재 값 | 위치 |
|---|---|---|
| 예: 보행자 좀비 코트 | `#4c5b52` | `js/data.js` ZOMBIES.walker |
- 캡처가 있으면 첨부. 없으면 "코드 분석 기반"이라고 명시

### 디자인 요구사항
- 목표 색상 HEX, 명도·채도 비율, 크기(px / 타일 비율), 레이어 순서, 애니메이션 시간(초)
- art-direction.md의 어떤 기준(팔레트, 음영, 형태 언어)을 따르는지 명시
- 구현 방법은 적지 않음 (개발 담당자가 결정)

### 완료 조건
- [ ] 판정 가능한 체크 항목 (예: 흑백 화면에서 적·건물·바닥이 구분됨)
- [ ] 낮/밤 전후 비교 스크린샷을 PR에 첨부

---
_그래픽/아트 디자인 리뷰에서 도출된 이슈입니다. 구현 방법은 개발 담당자가 결정합니다._
```

## 4. `gh` CLI 등록 수칙 (Windows PowerShell)

1. **`--body-file` 필수:** 백틱, 따옴표, 표가 PowerShell에서 깨지지 않도록 본문은 UTF-8(BOM 없음) 마크다운 파일로 저장한 뒤 전달합니다. 임시 파일은 **저장소 밖**(에이전트 스크래치 폴더)에 둡니다.
2. **명령 예시**
   ```powershell
   gh issue create --repo Reve1988/zombi-servivior --title "[Art] ..." --label design --body-file "<임시파일_절대경로>.md"
   gh issue comment <issueNumber> --repo Reve1988/zombi-servivior --body-file "<임시파일_절대경로>.md"
   ```
   - `PATH`가 아직 갱신되지 않았으면 `& "C:\Program Files\GitHub CLI\gh.exe" ...`로 실행합니다.
   - 에이전트 샌드박스에서는 네트워크가 막혀 있으므로, `gh`의 네트워크 명령은 사용자 승인 하에 실행합니다.
3. **중복 방지 · 스레드 선행 확인**: 등록/답변 전 `gh issue list --repo Reve1988/zombi-servivior --state all`과 `gh issue view <N> --comments`로 오너(무배지 일반 댓글) 및 타 에이전트 요청을 먼저 확인합니다.
4. **등록·납품·검수 후 동기화**: `share/design/` 납품 또는 `Gate 4` 시각 검수 완료 시 반드시 대상 이슈 `#N`에 `### 🎨 [디자이너 / Designer] → @{대상}` 코멘트를 남기고, `Project #1` (`Status`/`담당`) · 게이트 라벨 · `art-direction.md` · `share/STATUS.md`를 동기화합니다.
