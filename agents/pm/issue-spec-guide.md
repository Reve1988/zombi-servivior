# 기획 이슈 명세 표준 및 `gh` 운영 가이드 (`issue-spec-guide.md`)

기획(PM) 에이전트가 개발 에이전트에게 작업을 위임할 때는 반드시 본 문서의 **이슈 분할 기준 · 제목 규칙 · 본문 필수 항목**을 준수하여 GitHub 이슈를 생성합니다.

---

## 1. 이슈 분할 및 의존성 설계 원칙

1. **1 이슈 = 1 응집 기능 (`1 Feature Branch = 1 PR`)**:
   - 여러 시스템을 한 이슈에 과도하게 묶으면 PR 리뷰와 버그 추적이 어려워집니다.
   - 개발 에이전트가 `feature/{issueNumber}-{slug}` 브랜치 하나로 독립 구현·테스트할 수 있는 크기로 분할합니다.
2. **구현 순서 및 의존성 명시**:
   - 동시에 여러 연관 이슈를 발행할 때는 번호 순서대로 구현할 수 있도록 `1-1`, `1-2`, `1-3` 순번을 부여합니다.
   - 선행 이슈가 필요한 경우 본문 상단에 `> **선행 의존성**: #11 (지휘 본부 레벨 시스템) 구현 후 진행 권장` 형태로 GitHub 이슈 번호 링크(`#번호`)를 연결합니다.

---

## 2. 이슈 제목 및 라벨 컨벤션

### 제목 형식
```text
[기획/{영역} {페이즈}-{순번}] {핵심 구현 목표 요약}
```
또는 단일 밸런스 패치/개선일 경우:
```text
[밸런스/{영역}] {조정 대상 및 핵심 변경점}
```

- **영역 키워드 예시**: `레벨링`, `웨이브`, `몬스터`, `경제`, `전투`, `UI/UX`
- **작성 예시**:
  - `[기획/레벨링 1-1] 지휘 본부(HQ) Lv.1~4 증축, 단계형 테크 해금 및 자체 방어 포탑 시스템`
  - `[기획/웨이브 2-1] 주간 침공 방향 전술 브리핑 및 예상 이동 경로(Flow Field) 시각화`
  - `[밸런스/전투] 오라(Aura) 건물 동일 종류 중첩 감쇠 규칙 적용`

### 기본 라벨 (`--label`)
- 신규 기획·시스템 확장·밸런스 개편: `enhancement`
- 기획 의도와 다르게 작동하는 수치/공식 오류 수정: `bug`

## 3. 이슈 본문 필수 템플릿 (5대 섹션)

모든 기획 이슈 본문에는 아래 항목이 빠짐없이 포함되어야 합니다.

```markdown
## 📌 기획 배경 및 목적
- 현재 게임에서 발생하는 플레이 경험/밸런스 문제점과 본 시스템 도입으로 얻고자 하는 기대 효과 요약
- 필요 시 선행 의존성 이슈 번호(`#번호`) 명시

---

## 📊 수치 테이블 및 계산 공식
- 단계별 비용, 스탯 수치/배율, 쿨타임, 확률, 상·하한 캡(Cap)을 마크다운 표와 수식으로 명시
- 기존 코드(`js/data.js`, `js/game.js`)의 실제 식별자(`ITEMS`, `COZY_TIERS`, `popCap`, `powerShot` 등)를 병기하여 매핑 오차 방지

---

## ⚙️ 시스템 연동 및 예외 처리 규칙
- 주간 무료 이동(`M`) 시 상태 보존 여부
- 철거(`X`) 시 환급 비용 산출 기준 (기본 비용 + 강화 누적 비용의 80%, 무료 보급권 예외 등)
- 야간 블랙아웃(전력 방전) 시 작동 여부
- `localStorage` 기존 세이브 데이터 로드 시 신규 필드 기본값(Fallback) 호환 규칙

---

## 🖥️ UI/UX 및 연출 요구사항
- 상단 HUD, 우측 액션 패널, 하단 도크/상세 바(`#detail-bar`), 툴팁에 표시할 정보 및 버튼 동작
- 키보드 단축키(있는 경우) 및 캔버스 복셀 외형 변화·파티클·플로팅 텍스트·효과음 피드백 기준

---

## ✅ 완료 조건 (Acceptance Criteria)
- [ ] 개발 에이전트와 리뷰어가 구현 완료 여부를 명확히 판정할 수 있는 체크리스트 항목 1
- [ ] 체크리스트 항목 2
- [ ] 세이브/로드 호환성 및 예외 상황 검증 항목
```

## 4. `gh` CLI 이슈 등록 실행 수칙 (Windows PowerShell)

1. **본문 깨짐 방지를 위한 `--body-file` 필수 사용**:
   - 마크다운 내부의 백틱(`` ` ``), 따옴표, 줄바꿈이 PowerShell 인자 파싱 과정에서 훼손되지 않도록 본문은 반드시 UTF-8 마크다운 파일로 먼저 저장한 뒤 `--body-file` 옵션으로 전달합니다.
   - **주의**: 임시 본문 파일은 프로젝트 루트나 소스 폴더에 남기지 말고 에이전트 스크래치 영역 등 저장소 외부 임시 경로를 사용합니다.
2. **명령어 예시**:
   ```powershell
   gh issue create --repo Reve1988/zombi-servivior --title "[기획/레벨링 1-1] ..." --label enhancement --body-file "<임시파일_절대경로>.md"
   ```
   - 터미널 세션의 `PATH`가 아직 갱신되지 않아 `gh`를 인식하지 못할 경우:
   ```powershell
   & "C:\Program Files\GitHub CLI\gh.exe" issue create --repo Reve1988/zombi-servivior --title "[기획/레벨링 1-1] ..." --label enhancement --body-file "<임시파일_절대경로>.md"
   ```
3. **중복 등록 방지**:
   - 이슈 등록 전이나 재시도 시 `gh issue list --repo Reve1988/zombi-servivior`로 이미 동일 이슈가 올라갔는지 먼저 확인합니다.
